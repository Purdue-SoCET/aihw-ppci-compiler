# 07 — The IR (`ppci/ir.py`) and its Atalla extensions

## 7.1 Shape

* A `Module` holds `Variable`s, `Function`/`Procedure`s and `External*` declarations.
* A `SubRoutine` holds `Block`s; `entry` must be `blocks[0]`; every block ends with exactly one
  `FinalInstruction` (`Jump`, `CJump`, `JumpTable`, `Return`, `Exit`).
* Values are named (`Value.name`), typed (`Value.ty`), and track users (`used_by`). Names are made unique
  per function by `SubRoutine.make_unique_name` when the instruction is added to a block (`Block.add_instruction`
  `:592-599`), which is why the trace shows `num_1_17`, `tmp_10_20` etc.
* SSA: after `Mem2RegPromotor` scalar variables become values + `Phi` nodes; before it, and for
  address-taken variables, the IR uses `Alloc`/`AddressOf`/`Load`/`Store`.

## 7.2 Instruction reference (fields = `value_use` properties, i.e. use-tracked)

| Class | Fields | Notes |
|-------|--------|-------|
| `Alloc(name, amount, alignment)` | — | `ty = BlobDataTyp(amount, alignment)` |
| `AddressOf(src)` | `src` | `ty = ptr`; the only legal user of an `Alloc` for mem2reg |
| `Load(address, name, ty, volatile)` / `Store(value, address, volatile)` | `address`, `value` | address must be `ptr` (verifier) |
| `Const(value, name, ty)` | — | `value` int or float |
| `Binop(a, op, b, name, ty)` | `a`, `b` | ops `+ - * / % ^ | & >> <<` |
| `Unop(op, a, name, ty)` | `a` | `-`, `~` |
| `Cast(src, name, ty)` | `src` | |
| `Phi(name, ty)` | `inputs {block: value}` | `set_incoming` type-checks |
| `FunctionCall(callee, arguments, name, ty)` / `ProcedureCall` | `callee`, `arguments` | callee may be a `SubRoutine`, `ExternalSubRoutine` or a `ptr` value |
| `Jump(target)` / `CJump(a, cond, b, lab_yes, lab_no)` | | `cond ∈ {<, >, ==, !=, <=, >=}` |
| `Return(result)` / `Exit()` | | |
| `InlineAsm(template, clobbers)` | `input_values`, `output_values` | |

| **`VecOpMasked(op, arg1, arg2, mask, name, ty)`** | | `:1416`; `op ∈ ["+","-","|","<<","*","&",">>","/","^","GEMM","EXP","SQRT","~","RSUM","RMIN","RMAX"]` |
| **`VecIndex(arg1, index, name, ty)`** | | `:1445` |

| **`LoadWeights(arg)`** | | `:1489`, side-effect instruction |
| **`ScpadLoad(x,y,z)` / `ScpadStore(x,y,z)`** | | `:1504`, `:1527`, integer operands |
| **`VectorLoad(addr, arg2, arg3, arg4, name, ty)`** | | `:1550` |
| **`VectorStore(vec, addr, arg2, arg3, arg4)`** | | `:1580` |
| **`SqrtBf(a, name, ty)`** | | `:1614` |

The textual IR printer (`irutils/writer.py`, used by `Module.display()` and `--ir`) prints the new nodes
with their `__str__` (`gemm a, b, m`, `vecop_masked + a, b, m`, `vector_load …`). **The IR reader
(`irutils/reader.py`) has not been extended** (grep finds no `vecop_masked` there), so `--ir` output
containing intrinsics cannot be read back. (Verified by grep; Inferred consequence.)

## 7.3 Builder helpers (`ppci/irutils/builder.py:46-215`)

`Builder.emit(instruction)` appends to the current block and attaches a `DebugLocation` if a source
location is active. `emit_binop`, `emit_load`, `emit_cast`, `emit_const`, plus Atalla helpers
`emit_gemm`, `emit_vec_index`, `emit_vec_op_masked`, `emit_make_mask`, `emit_load_weights`,
`emit_scpad_load/store`, `emit_vector_load` (name `tmp_vload`), `emit_vector_store`, `emit_sqrt_bf`.

## 7.4 Verifier changes

`ppci/irutils/verify.py:131-137`: for `Binop` with `VectorTyp` result, it is an error only if
**neither** operand is the vector type. Everything else is upstream. The verifier runs before and after
`optimize()` and once more in `ir_to_stream` (`api.py:266`), so any IR reaching the backend satisfies it.

## 7.5 Example IR (from `atalla_tests/vv_instr.c`, `-O2`, verified output)

```
global function i32 main() {
  main_block0: {
    i32 num_68 = 43981;
    i32 num_1_70 = 1;
    i32 num_2_71 = 31;
    vector_load num_68, num_1_70, num_2_71, num_1_70;     ; tmp_vload_72 (name not printed by __str__)
    i32 num_4_73 = 57005;
    vector_load num_4_73, num_1_70, num_2_71, num_1_70;
    vec tmp_14_75 = tmp_vload_72 + tmp_vload_11_74;
    vec tmp_19_77 = tmp_14_75 - tmp_vload_11_74;
    vec tmp_24_78 = tmp_19_77 * tmp_vload_11_74;
    i32 num_30_79 = 5;
    gemm tmp_24_78, tmp_24_78, num_30_79;                 ; tmp_gemm_82
    i32 num_38_83 = 43690;
    vector_store tmp_gemm_82, num_38_83, num_1_70, num_2_71, num_1_70;
    i32 num_46_85 = 0;
    return num_46_85;
  }
}
```

Observations: all `vec` locals were promoted to SSA (no allocas remain); constants were CSE'd
(`num_1_70` reused); `v6 = v5` copy vanished; the `gemm` mask is a plain `i32` value (the IR allows
`IntegerTyp` masks; the backend inserts `mv_stm`).
